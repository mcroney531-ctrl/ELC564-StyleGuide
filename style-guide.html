03

Interaction States

One documented feedback language, used identically across all six scenarios: attempt → corrective retry → success.

The three-state feedback loop

1 · Initial attempt
2 · Corrective (retry)
Not quite

Explains why, then offers "Try again" — same question, not a new one.

3 · Success
Correct

Brief affirmation, then advance to the next scenario.

State 2 always loops back to state 1 on the same question — it never branches to a different follow-up question. That keeps the retry path predictable and the content scope finite.

Callouts

iNeutral, informational note.
✓Positive confirmation, same green as confirmed-correct.
!Attention needed — same amber as "in progress."
✕Problem or block — same red as confirmed-wrong.

Hover / selected / completed, at a glance

  • • Hover — cards lift 8px with a spring bounce; buttons and options tighten their border and darken slightly.
  • • Selected — an option gets a solid ink border and tint the instant it's clicked, before it's known to be right or wrong.
  • • Completed — a cluster's progress badge switches from gray "Not started" to amber "In progress" to green "Complete," and its section's two progress ticks fill in as each scenario is solved.

Motion

Two easing conventions and two moments — used with enough restraint that the one signature moment still reads as signature.

Easing conventions

Standard — everything else
cubic-bezier(.65,0,.35,1)
Out — reveals & fades
cubic-bezier(.16,1,.3,1)
Bounce — hover only, the one exception
back.out(2.2)

The standard and "out" curves are both decelerating with no overshoot — they're what make the transition and feedback reveals feel engineered rather than playful. Overshoot is reserved for exactly one place: the card hover. Try it on the card in Components above.

The signature transition, in the actual code

The card-to-section move uses GSAP's Flip plugin rather than a hand-rolled position tween, because Flip tracks the real First/Last rects for us instead of hard-coding coordinates:

  1. First — Flip.getState(card) captures the clicked card's exact position and size while it still sits in the grid.
  2. Last — the section element is already laid out full-screen (position:fixed; inset:0) in the DOM, just invisible.
  3. Invert & Play — Flip.from(state, {targets: section}) applies the captured card rect to the section, then animates it to the section's natural full-screen layout — so the section appears to grow out of the card. Sibling cards fade and scale down 6% in parallel so attention stays on the one expanding.
  4. Reverse — on exit, Flip.getState(section) captures the full-screen rect, Flip.fit(section, card) instantly re-parents its geometry onto the card's position, then Flip.from() animates the shrink back — the same technique, run backwards.

Corner radius is cross-faded from 20px (card) to 0 (full-bleed section) across the same duration, which is what sells the "one object changing size," not two objects cutting between each other.

05

Imagery & Illustration

One card mark per cluster, drawn to a shared formula rather than commissioned as three unrelated pieces.

Treatment: duotone line art on a 240×240 grid — a 4px ink-navy outline plus one flat cluster-accent fill, no gradients, no photography, no character work.
Production: hand-coded inline SVG, not AI-generated raster art. That was a deliberate call: at this restrained a visual register, coded shapes stay crisp at any size, recolor instantly through the same CSS variables as everything else, and cost nothing in file weight — a better production asset here than a generated image would have been.
Direction given (the brief these would follow if handed to an illustrator or an image model instead): abstract the concept into one clear motif — an inbound document for Bring, an inspected shield for Verify, a human figure kept larger and in front of a small AI node for Stay Present — render each in the same duotone treatment, same stroke weight, same panel proportions, no literal photography or mascot-style characters.
